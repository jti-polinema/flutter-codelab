Fitur yang berjalan di satu perangkat belum tentu bebas dari masalah. Melalui codelab ini, Anda akan berlatih menulis pengujian yang membantu memeriksa perilaku aplikasi, menemukan regresi, dan menjaga kualitas kode saat aplikasi berkembang.

Tujuan pembelajaran

Setelah menyelesaikan codelab ini, Anda diharapkan mampu:

  • menentukan bagian aplikasi yang perlu diuji dengan pengujian unit, widget, atau integrasi;
  • menulis pengujian unit untuk logika dan kasus tepi;
  • menguji tampilan serta interaksi widget Flutter;
  • memisahkan dependensi agar kode mudah diuji, termasuk dengan fake repository;
  • menjalankan pengujian integrasi dan menggunakan cakupan kode sebagai bahan evaluasi.

Persiapan

  • Project Flutter yang pernah Anda kerjakan, atau project baru dengan flutter create testing_lab.
  • Flutter SDK, Dart, VS Code atau Android Studio, dan emulator atau perangkat Android.
  • Pemahaman dasar tentang fungsi Dart, class, widget, dan Future.

Catatan penggunaan AI. Anda boleh meminta AI membantu menyusun skenario atau menjelaskan pesan kegagalan. Tetap periksa sendiri bahwa pengujian benar-benar memeriksa perilaku yang dimaksud. Pengujian yang sekadar lulus, tetapi tidak akan gagal ketika fitur rusak, belum memberi perlindungan yang berarti.

1. Pilih jenis pengujian yang tepat

JenisYang diperiksaContoh
UnitSatu fungsi atau objek tanpa merender UIValidasi judul tugas atau aturan bisnis
WidgetTampilan dan interaksi satu atau beberapa widgetForm menampilkan pesan saat input tidak valid
IntegrasiAlur aplikasi dari awal hingga akhir pada perangkat atau emulatorPengguna menambah tugas dan melihatnya di daftar

Pengujian unit biasanya paling cepat dan mudah diperbaiki. Pengujian widget memeriksa UI tanpa perlu menjalankan aplikasi pada perangkat. Pengujian integrasi mencakup alur yang lebih utuh, tetapi waktu eksekusi dan pemeliharaannya lebih besar.

2. Rancang kode agar mudah diuji

Logika bisnis yang bercampur langsung dengan widget dan akses jaringan sulit diuji secara terpisah. Pisahkan tanggung jawab: widget menangani tampilan dan interaksi, sedangkan repository menangani sumber data. Berikan repository melalui konstruktor atau abstraksi agar pengujian dapat menggantinya dengan data tiruan yang terkendali.

Mulailah dari perilaku yang penting bagi pengguna. Tidak semua baris kode perlu pengujian tersendiri, tetapi aturan bisnis, validasi, dan alur utama sebaiknya memiliki pemeriksaan yang jelas.

1. Tulis pengujian berdasarkan perilaku

Contoh berikut memeriksa aturan sederhana: judul tugas harus berisi teks setelah spasi di awal dan akhir diabaikan.

bool isValidTaskTitle(String value) {
  return value.trim().isNotEmpty;
}

Buat file test/is_valid_task_title_test.dart. Paket flutter_test sudah tersedia dalam project Flutter.

import 'package:flutter_test/flutter_test.dart';
import 'package:testing_lab/is_valid_task_title.dart';

void main() {
  group('isValidTaskTitle', () {
    test('menerima judul yang berisi teks', () {
      expect(isValidTaskTitle('Belajar Flutter'), isTrue);
    });

    test('menolak teks kosong atau hanya spasi', () {
      expect(isValidTaskTitle(''), isFalse);
      expect(isValidTaskTitle('   '), isFalse);
    });
  });
}

Sesuaikan nama package pada baris import dengan nama project Anda di pubspec.yaml.

2. Gunakan pola Arrange, Act, Assert

  • Arrange: siapkan data dan objek yang dibutuhkan.
  • Act: panggil fungsi atau lakukan tindakan yang diuji.
  • Assert: periksa hasilnya dengan expect.

Tambahkan kasus tepi yang relevan, misalnya masukan kosong, spasi saja, nilai batas, atau kegagalan yang mungkin terjadi. Jangan hanya menguji kasus yang diperkirakan berhasil.

1. Pisahkan kontrak sumber data

Jangan mengandalkan API sungguhan dalam pengujian unit. Jaringan, autentikasi, dan isi server dapat berubah, sehingga pengujian menjadi lambat atau tidak konsisten. Definisikan kontrak kecil untuk kebutuhan fitur:

abstract interface class TaskRepository {
  Future<List<String>> getTasks();
}

class TaskService {
  TaskService(this._repository);

  final TaskRepository _repository;

  Future<List<String>> loadTasks() {
    return _repository.getTasks();
  }
}

2. Ganti API dengan fake repository

Fake adalah implementasi sederhana yang perilakunya dikendalikan pengujian. Dengan fake, Anda dapat memeriksa hasil sukses maupun kegagalan tanpa koneksi internet.

class FakeTaskRepository implements TaskRepository {
  FakeTaskRepository({this.tasks = const [], this.error});

  final List<String> tasks;
  final Exception? error;

  @override
  Future<List<String>> getTasks() async {
    if (error != null) throw error!;
    return tasks;
  }
}

test('meneruskan data dari repository', () async {
  final service = TaskService(
    FakeTaskRepository(tasks: ['Baca materi']),
  );

  expect(await service.loadTasks(), ['Baca materi']);
});

Tambahkan pengujian kegagalan untuk memastikan error tidak berubah diam-diam menjadi daftar kosong. Pilih penanganan error yang memang dijanjikan oleh rancangan aplikasi.

1. Bangun widget dan periksa hasilnya

Pengujian widget berjalan dengan flutter_test. Gunakan pumpWidget untuk merender UI, lalu cari elemen dengan find dan periksa kondisi yang terlihat oleh pengguna.

testWidgets('menampilkan judul halaman tugas', (tester) async {
  await tester.pumpWidget(
    const MaterialApp(
      home: Scaffold(
        body: Text('Daftar tugas'),
      ),
    ),
  );

  expect(find.text('Daftar tugas'), findsOneWidget);
});

2. Uji interaksi pengguna

Untuk menguji form atau tombol, masukkan teks dengan enterText, tekan kontrol dengan tap, lalu panggil pump atau pumpAndSettle agar perubahan UI selesai dirender.

await tester.enterText(
  find.byKey(const Key('task-title-field')),
  'Baca materi',
);
await tester.tap(find.byKey(const Key('save-task-button')));
await tester.pumpAndSettle();

expect(find.text('Baca materi'), findsOneWidget);

Berikan Key pada kontrol jika pencarian berdasarkan teks atau tipe widget tidak cukup jelas. Uji juga keadaan penting seperti input tidak valid, indikator loading, data kosong, dan pesan error.

Hindari jeda waktu tetap seperti Future.delayed hanya agar pengujian lulus. Gunakan mekanisme pemompaan waktu dan animasi yang disediakan oleh Flutter Test.

1. Jalankan alur pada perangkat

Pengujian integrasi memeriksa beberapa bagian aplikasi yang bekerja bersama. Flutter menyediakan paket integration_test. Jika belum ada, tambahkan pada bagian dev_dependencies di pubspec.yaml, lalu jalankan flutter pub get:

dev_dependencies:
  integration_test:
    sdk: flutter

Letakkan pengujian di integration_test/app_test.dart dan gunakan binding berikut:

import 'package:flutter_test/flutter_test.dart';
import 'package:integration_test/integration_test.dart';
import 'package:testing_lab/main.dart' as app;

void main() {
  IntegrationTestWidgetsFlutterBinding.ensureInitialized();

  testWidgets('pengguna dapat menambahkan tugas', (tester) async {
    app.main();
    await tester.pumpAndSettle();

    await tester.enterText(
      find.byKey(const Key('task-title-field')),
      'Baca materi',
    );
    await tester.tap(find.byKey(const Key('save-task-button')));
    await tester.pumpAndSettle();

    expect(find.text('Baca materi'), findsOneWidget);
  });
}

Sesuaikan kunci widget dengan aplikasi Anda. Jalankan pengujian pada emulator atau perangkat yang aktif:

flutter test integration_test/app_test.dart -d <device_id>

2. Cegah regresi dengan menguji ulang

Setelah menemukan dan memperbaiki bug, tambahkan pengujian yang gagal sebelum perbaikan dan lulus sesudahnya. Jalankan seluruh suite secara berkala dengan flutter test, bukan hanya pengujian yang baru ditulis.

Gunakan fitur utama project Anda. Jika belum ada, buat fitur daftar tugas sederhana. Tujuannya adalah menguji perilaku dari logika hingga alur aplikasi, bukan mengejar jumlah pengujian sebanyak-banyaknya.

  1. Catat perilaku: tuliskan sedikitnya tiga skenario, termasuk satu kasus tepi dan satu kegagalan.
  2. Uji logika: buat pengujian unit untuk validasi atau aturan bisnis. Kelompokkan kasus dengan group.
  3. Uji dependensi: pisahkan akses data melalui repository, lalu buat fake untuk data sukses dan error.
  4. Uji UI: periksa tampilan awal, masukan tidak valid, dan tindakan pengguna yang berhasil.
  5. Uji alur utama: tulis satu pengujian integrasi untuk alur penting yang melibatkan beberapa bagian aplikasi.
  6. Jalankan semua pemeriksaan: gunakan flutter test, flutter test integration_test/app_test.dart -d <device_id>, dan flutter analyze. Perbaiki kegagalan sebelum melanjutkan.

Jika sebuah pengujian gagal, baca keluaran yang menunjukkan pengujian serta kondisi yang tidak terpenuhi. Pastikan penyebabnya bukan karena urutan test, data bersama, atau ketergantungan pada jaringan.

1. Gunakan cakupan sebagai petunjuk

Untuk menghasilkan laporan cakupan pengujian unit dan widget, jalankan:

flutter test --coverage

Angka cakupan menunjukkan bagian kode yang dijalankan saat pengujian, bukan jaminan bahwa semua perilaku sudah diperiksa. Tinjau cabang penting dan kasus tepi; jangan menambah pengujian yang tidak memeriksa hasil hanya demi menaikkan persentase.

2. Tugas

  1. Tambahkan pengujian unit dan widget untuk fitur utama project Anda, termasuk kasus sukses, input tidak valid, dan error yang relevan.
  2. Tambahkan satu pengujian integrasi untuk alur utama. Jika tidak dapat dijalankan di perangkat, jelaskan kendalanya dan sertakan perintah yang digunakan.
  3. Catat skenario, hasil flutter test, hasil analisis, dan temuan yang belum terselesaikan di README.md.
  4. Kirim perubahan melalui repository Git sesuai arahan dosen.
